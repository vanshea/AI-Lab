## Wave 2: Correctness and Swift 6 concurrency

Important context: the project uses Swift 6 mode but does **not** set `SWIFT_DEFAULT_ACTOR_ISOLATION` or `SWIFT_APPROACHABLE_CONCURRENCY`, so types are non-isolated by default. Audit isolation explicitly instead of assuming UI types are on the main actor.

- **`HealthKitManager.swift`:** check `HKHealthStore.isHealthDataAvailable()` first; handle every authorization state (remember HealthKit hides read-denial, so the app must behave sanely when no data comes back); use correct sample types, units, and "today" predicates (exercise time in minutes; sleep filtered to asleep stages, not in-bed); write `HKStateOfMind` correctly for iOS 17 and surface write failures to the user instead of swallowing them; make sure results hop to the main actor before touching UI state; never block first render on authorization.
- **`SelfCareModel.swift`:** the persistence mechanism must round-trip (save, relaunch, load). Test first launch (no data) and corrupt or unreadable data (must not crash). "Today" logic must use the user's current calendar and `startOfDay`, and survive midnight rollover, DST changes, and travel across time zones. Define and enforce what happens on a second check-in the same day (update vs duplicate). Deleting a factor must not corrupt past check-ins.
- **Lifecycle:** a daily app must refresh when it returns to foreground on a new day (`scenePhase`).
- **Concurrency:** any Swift 6 diagnostic is a 🔴. Look for non-`Sendable` values crossing isolation, missing `@MainActor` on UI-facing state, and closures capturing `self` where a cycle is possible.
- **Smells to grep and remove:** force unwraps, `try!`, `as!`, `fatalError`, stray `print(`, `TODO`/`FIXME`, dead code, placeholder copy.
- **Tests:** there is a single test file. Run it, judge whether it tests anything meaningful, and add tests for date rollover/DST, persistence round-trip, factor deletion, and the HealthKit-denied path (use a protocol seam or stub so these run without a device).

## Wave 2b: Apple Health integration for iOS 27

Goal: make Self Care a first-class citizen in Apple Health, including the redesigned Health app arriving with iOS 27.

**What is and is not known (press reports as of October 2026; verify against Apple's documentation):**
- The redesigned Health app (new Insights and Longevity areas, card-based Browse, faster sync) is in the **iOS 27.2 beta** and is reported as **not shipping with the 27.2 release**. It is expected later this year. Sources: [MacRumors hands-on](https://www.macrumors.com/2026/09/16/ios-27-2-health-app-beta/), [MacRumors iOS 27 Health guide](https://www.macrumors.com/guide/ios-27-health-app/).
- **No new third-party "integrate into the Health app" API has been documented.** One developer write-up ([Sahha](https://sahha.ai/blog/ios-27-health-fitness-developers/)) says the HealthKit read/write API is essentially unchanged, and none of the reports mention State of Mind changes. Treat both as unconfirmed.
- So integration happens through **HealthKit**. **Do not invent APIs, entitlements, or URL schemes.** If you believe a new iOS 27 API exists, prove it by finding the symbol in the installed SDK headers or in Apple's documentation, and cite where.

**Step 2: Make the existing HealthKit integration excellent.** All of this is available from iOS 17.

- **Rich State of Mind samples.** Write `HKStateOfMind` with a deliberately chosen kind (momentary emotion vs daily mood, matching what the check-in actually captures), a correctly mapped valence (document the slider-to-valence mapping and test the endpoints and midpoint), labels, and associations. Entries should look meaningful wherever the Health app surfaces State of Mind, not just exist.
- **No duplicates, no drift.** Editing today's check-in must update the Health sample, not add a second one. Use HealthKit's sync identifier and sync version metadata so a re-save replaces the earlier sample. Deleting a check-in in Self Care must delete the Health samples the app wrote. On foreground, reconcile with Health so that edits or deletions made in the Health app do not leave the two silently out of sync. Propose the minimal reliable approach (for example an anchored object query) and implement it if it is small.
- **Authorization in context.** Ask for Health access after explaining why, never at launch. The app must be fully usable with every Health permission denied. Remember HealthKit hides read-denial, so design for "no data came back." If access was denied, explain how to change it in Settings and Health's data-access screen.
- **App identity in Health.** The app appears in Health's data sources and access lists by name and icon. Verify the display name and app icon read clearly at small sizes.
- **Forward compatibility.** Gate any iOS 27-only API behind an availability check and keep the deployment target at 17.0 unless the human decides otherwise (put that decision in `HUMAN_TODO.md`). Build with the latest installed SDK.
- **Do not duplicate Health.** Health now has Insights, readiness, and a "Health Age" estimate. Self Care's job is the reflective daily check-in. Do not add health scoring, and make sure no copy implies diagnosis, prediction, or medical benefit.
- **Naming and branding.** Refer to "Apple Health" correctly in Settings copy and App Store metadata. Do not use Apple's Health app icon or a "Works with Apple Health" badge unless you have verified Apple's current identity and marketing guidelines allow it.
